# AIPI5's own dependencies.
#
# Short, because most of what this assistant runs on is AIA's — install AIA's
# requirements too, into the same virtualenv:
#
#     pip install -r ~/AI_Assit/requirements.txt
#     pip install -r requirements.txt
#
# That brings numpy, sounddevice, webrtcvad, vosk, pypinyin, sherpa-onnx and
# requests, which is the whole of the voice path. Nothing below duplicates any
# of it.

# The configuration file. The one dependency that is purely this project's.
PyYAML

# The conversational model. Version 1.x — the client is `openai.OpenAI(...)`
# and the 0.x module-level API is not compatible with anything in
# aipi5/llm/client.py.
openai>=1.0

# Requests is already pulled in by AIA, and is named here because this project
# uses it directly for the weather and the news feeds. Listing a transitive
# dependency you import is not redundancy — it is what stops an unrelated
# change in AIA from breaking this one silently.
requests

# Web push, so the Pi can ring a phone whose app is closed. Only needed for
# outgoing calls; everything else works without it.
#
# **The versions are pinned, and the pin is load-bearing.** Installing current
# pywebpush pulls `cryptography>=47`, and this Pi's venv sees the system
# `python3-openssl`, which requires `cryptography<45`. Upgrading therefore
# breaks pyopenssl inside the venv — measured, as
# `AttributeError: module 'lib' has no attribute 'GEN_EMAIL'` — while leaving
# every import AIPI5 itself does working, so nothing looks wrong until
# something reaches for TLS through pyopenssl.
#
# 1.14.1 is the last line that supports the cryptography the system ships.
# Before changing it, check what `python3-openssl` on the device requires.
pywebpush==1.14.1
py-vapid==1.9.0

# The ceiling the paragraph above only *describes*. Until this line existed it
# was held by accident: nothing in this file constrained cryptography, and the
# only reason a working version was installed is that pywebpush's own pin
# happened to resolve to one. `pip install -U cryptography`, or any change in
# how pip resolves, would silently produce the exact breakage documented above.
#
# The bound is measured, not guessed — `dpkg -s python3-openssl` on this device
# reports `Depends: python3-cryptography (<< 45), python3-cryptography
# (>= 41.0.5)`, and 43.0.0 is what is installed. `aipi5/call/push.py` imports
# cryptography directly, so it is this project's dependency and not only
# pywebpush's.
cryptography>=41.0.5,<45

# Imported directly by this project and supplied by AIA's requirements, which
# `scripts/deploy.sh` installs first. Named here for exactly the reason
# `requests` is named above: listing a transitive dependency you import is what
# stops an unrelated change in AIA from breaking this one silently.
#
#   numpy        aipi5/vision/person_detection.py — decoding detector output
#   sounddevice  aipi5/main.py — enumerating capture devices at startup
#
# Both are pip packages inside the venv, unlike cv2, which is the system build
# (see the apt note below). Neither is pinned: AIA chooses the versions and
# this file should not fight it.
numpy
sounddevice

# A QR code on the screen, so a phone can open the Google Photos picker.
#
# The kiosk has no keyboard and no address bar, and the picker has to be opened
# in a browser signed in to the account — so the URL has to leave this device
# by being photographed. segno is pure Python with no dependencies of its own,
# which matters on a Pi whose venv sees system packages: it cannot drag in a
# second copy of anything already installed.
#
# **Optional.** `aipi5/photos/qr.py` imports it inside a try, and without it
# the settings page shows the URL as text instead — usable over ssh, not usable
# on the panel. Nothing else in the project touches it.
segno

# ── on the Pi, and not from PyPI ──────────────────────────────────────
#
# Two things this project needs are Debian packages rather than wheels, and
# installing them with pip either fails or produces something that does not
# work against the system libraries:
#
#     sudo apt install python3-opencv         # the camera, over V4L2
#     sudo apt install hailo-all              # HailoRT, for the AI HAT+ 2
#
# Both are optional. Without OpenCV there is no camera and no person detection;
# without hailo-all, person detection needs `backend: cpu` and the package
# below.
#
# python3-opencv rather than `pip install opencv-python`: the venv already sees
# system packages for hailo_platform's sake, the Debian build links the system
# V4L2 and JPEG libraries this camera path goes through, and it is one apt line
# against a wheel that is 60 MB and, on some aarch64 images, a source build. If
# a deployment would rather have the wheel, `opencv-python-headless` in the
# venv works — nothing here imports anything but `cv2.VideoCapture`,
# `cv2.imwrite` and two constants.
#
# The camera is a USB UVC device — a Logitech Brio 101 — which is why this is
# OpenCV and not picamera2. picamera2 speaks to libcamera on the CSI ribbon
# connector and does not see a webcam at all.
#
# onnxruntime is only needed for that CPU fallback, and is deliberately not a
# hard requirement — it is 50 MB of wheel for a code path a Pi with an AI HAT+
# never executes. Install it if you need it:
#
#     pip install onnxruntime
