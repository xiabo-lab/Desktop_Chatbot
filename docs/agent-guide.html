AIPI5 · Raspberry Pi 5 · reached from your phone

There is now an agent inside AIPI5.

The assistant answers questions. The agent looks at the device, changes it, checks the change worked, and puts it back when it did not. This is how to use it, and — just as usefully — what it will refuse to do.

Where it lives

On your phone, in the same web app you use to call the device. Open it on the tailnet and there is a new button on the home screen beside Files: 

https://aipi5.tail250c52.ts.net

   📞 Call AIPI5
   ⇅ Files
   ⚙ Agent        ← here

Tap it and you get a chat. Type a question, get an answer. A blue dot on the button means something happened while you were elsewhere — a run finished, or it is waiting for you to approve something.

Deliberately not on the touchscreen. The agent is for when you are not standing in front of the device — the screen is for the assistant, the slideshow and the games.

Worth knowing

Opening the console replays the whole conversation from the beginning. That is what makes it survive a restart: when the agent restarts the assistant, your phone loses its connection for fifteen seconds, then reconnects and is handed everything it missed.

Asking it things

asks nothing

Anything about the state of the device. It picks its own tools, reads the real thing, and answers from evidence rather than from what a Raspberry Pi is usually like.

agent
Why did Kodama-Lite last restart, and is it running now?
✓ service_status — is kodama-lite running
✓ read_journal — the kodama-lite log
Kodama-Lite is not running now. It is inactive (dead). There is no recorded restart reason in the available log. Its status shows: Restarts: 0 Last exit status: 0 — a clean exit The service is also disabled, so it is not configured to start automatically.
3 steps · 4.5s

A real exchange from the device. Nothing here needed your permission.

Things worth asking

  • “How much disk space is left?”
  • “Is the assistant running, and has it restarted recently?”
  • “Why did the screen go blank last night?”
  • “What time does the photo slideshow start?”
  • “What have you changed on this device?”
A real limit, not a bug

It only ever sees warnings and errors in the logs. Ordinary log lines on this device include the text of things people said out loud in the room, and what the agent reads gets sent to OpenAI. So the floor is built in — there is no setting for it.

The practical consequence: “nothing in the log” means no complaints, not no activity. The agent knows this and will usually say so.

Changing a setting

asks you first

Ask in plain words. You get a card showing the exact line that would change — not a description of it, the line — and nothing happens until you tap.

agent
Change the slideshow start time from 7 AM to 8 AM.
✓ read_config_file — aipi5.yaml
Change screensaver.day_start from "07:00" to "08:00"
screensaver.day_start
-  day_start: "07:00"
+  day_start: "08:00"
This also blanks the touchscreen for ten to twenty seconds, because aipi5-ui.service is PartOf=aipi5.service. The phone console goes quiet for the same window and reconnects by itself.
NoDo it
✓ set_config
Changed the slideshow start time from 07:00 to 08:00. The assistant restarted and is healthy.
2 steps · 19.1s

What happens after you tap

Eleven steps, and you only see the last one. The file is copied aside, the line is changed, the file is re-parsed to check it still loads, the assistant is restarted, and its health is verified three separate ways — the unit is active, its own page answers, and the log carries no traceback.

If any of that fails, the old value goes back automatically and the assistant is restarted on it before you are told anything. A rollback is the system working, not a failure to worry about.

Undoing something

“Undo that” works, and so does “what have you changed?”. Undoing needs no approval — it is the safe direction.

Tested

A change was applied and then rolled back on the device, and afterwards config/aipi5.yaml was byte-identical to before — every comment intact, and the deliberate local settings this device carries (like calling being switched on) untouched.

Putting a page on the screen

asks nothing

“Open YouTube.” A second browser appears over the touchscreen, driven by the agent. It is a different browser from the kiosk with its own profile, so nothing it does can disturb the assistant’s own page.

agent
Open duckduckgo.com, search for “Raspberry Pi 5 review”, take a screenshot, then close the browser.
✓ browser_open
✓ browser_type
✓ browser_screenshot
✓ browser_close
Searched DuckDuckGo for “Raspberry Pi 5 review,” saved a screenshot, and closed the browser. Screenshot: agent-20260827-100255.jpg in the phone’s Files screen.
5 steps · 16.1s

It works a page the way you would: open, read what is there, click something, read again. Screenshots land in the shared folder, so they show up on the Files screen of the same app.

Say “close the browser” when you are done, or use the × on the window. It closes itself after half an hour untouched, but a window left over the kiosk makes the device look broken to anyone walking past.

Fixed

It used to be ten minutes, and it measured the wrong thing: the timer only noticed the agent touching the page, so a browser you were reading yourself looked idle and was closed out from under you. It now counts your own use as use, and waits three times as long.

When a page needs you

A verification box, a sign-in, a cookie wall — things the agent cannot and must not do itself. It leaves the page up, tells you what to tap, and waits. The window keeps its own controls, so you finish the job and tell it to carry on.

agent
Search Google for dragon ball and tell me the top results.
✓ browser_open
✓ browser_hand_over
Google is showing an “unusual traffic” verification page. Tap the verification box on the AIPI5 screen, then tell me when it’s complete. I’ll read the top results without closing the page.
3 steps · 7.8s

It used to close the browser instead, within a second, which took away the one thing you could have acted on. A page waiting on you keeps the screen for a full hour, longer than any other, because the job can mean finding a password or fetching a phone.

If a page traps you

It cannot. The window is an ordinary browser window with a title bar, so there are four ways out and none of them needs the agent: the × at the top right closes the window, the × on the tab closes the page, ← goes back, and the address bar takes you elsewhere.

It used to open full-screen with no controls at all, which meant a modal advertisement or a consent wall held the screen until the agent closed it or ten minutes went by. That was a real fault, and it is fixed.

Advertising

The browser blocks the large ad networks, the tracking scripts and the “allow notifications” popups — around seventy domains, in a list only root can edit.

What no blocker will stop

YouTube’s own ads. They arrive on the same connection as the video, from the same servers — so no domain-level blocker removes them, Pi-hole included. Blocking those hosts does not remove the advertisement; it removes YouTube.

uBlock Origin would work, because it filters inside the page rather than at the network. It cannot be installed here: Debian ships the Manifest V2 build, and this Chromium refuses those — silently, without even a line in the log.

What it cannot open

Only http:// and https://. Not file://, not this device’s own services, not anything else on your home network. Those are refused by the privileged half of the system, not by the agent’s good manners.

Using your hand

asks nothing

Once a page is on the screen you can work it from where you are standing. The camera watches for one hand. Hold it up, palm towards the camera, and the page follows.

What you doWhat happens
Open palm, sweep upwardScrolls up
Open palm, sweep downwardScrolls down
Open palm, sweep right to leftBack, to the previous page
Open palm, sweep left to rightForward again, if there is anywhere to go
Open palm, held still and driftingMoves the pointer
Close your hand into a fistClicks where the pointer is

Directions are from where you are standing, not from the camera’s point of view. Sweeping to your right moves forward; the picture is mirrored for you, the way a mirror is.

Aiming a click

There is no cursor drawn on the screen, and there cannot be. The hand tracking runs inside the assistant’s own page, which at that moment is underneath the browser you are looking at — anything it drew would be drawn behind the window.

So the page itself shows you where you are pointing. Move your open palm and the thing under the pointer lights up the way it would under a mouse: links underline, buttons brighten, a video shows its controls. That is the site doing it, in the window you are watching. Line the highlight up with what you want, then close your hand.

Worth knowing

Your hand does not have to reach the edges of the camera’s view. The middle of the frame is stretched across the whole page, so a comfortable range of movement covers the corners.

When it is listening

Only while the agent has a page open. The moment the browser closes, the camera stops being read for hands and the assistant goes back to what it was doing. Nothing is watching for gestures the rest of the time.

The touchscreen keeps working throughout. Hand control is a longer arm, not a replacement — every gesture does something you could have done by walking over and touching the glass.

If it is not responding

  • Stand where the camera can see you. The same view the assistant uses to notice somebody is in the room.
  • Make the sweep bigger and slower. It has about five looks a second, and needs a movement across roughly a quarter of the frame before it counts as a sweep rather than a shrug. A quick flick can happen entirely between two frames.
  • Spread your fingers. An open palm means five fingers showing. A half-open hand is neither shape and is ignored, which is deliberate.
  • One person at a time. If two people are in view it follows the hand nearest the middle of the picture.
  • One gesture at a time. After a sweep it waits about half a second, so a single movement scrolls once rather than three times.

What a hand cannot do

It cannot type. It cannot reach the address bar, the tabs or the window controls — not because those are blocked, but because the pointer a gesture moves exists only inside the page and the browser’s own furniture is not somewhere it can be sent.

It also cannot open a browser. Waving at a device showing the assistant does nothing at all; the page has to be there first, and putting it there is something you ask the agent for.

And it changes nothing about approvals. A gesture is your own input, the same as a touch — it is not the agent deciding to do something, so there is nothing extra to approve.

Reminders

asks nothing

“Remind me in two minutes to check the oven.” It works out the absolute time from what you said, tells you what it set so a mistake is visible before it is a missed appointment, and the notification arrives on your phone.

Reminder set for Thursday, August 27, at 11:50 AM: “Check the oven.”
2 steps · 3.9s

They live on disk, so they survive the device being rebooted. Ask “what reminders are waiting?” to see them, and “cancel the one about the oven” to drop one.

Not set up yet

Email delivery is built but not switched on. Four steps in the Google Cloud console are needed first — they are written out in docs/gmail-setup.md on the Pi. Until then, reminders arrive as phone notifications, which is enough for most of what a reminder is for.

Things it remembers

asks nothing

Say “remember that…” and it carries into every later conversation. Useful for the things you would otherwise repeat: what you call something, which app you mean, where something lives. 

you   Remember that when I say music I always mean Kodama.
agent Got it. “Music” means Kodama, never Spotify.

           ── a completely separate conversation ──

you   If I asked you to put some music on, what would you use?
agent Kodama — specifically kodama-lite.service.
       0 tool calls · it already knew

Keep them short: they are shown to the agent at the start of every future conversation, so a long one is a permanent tax. “Forget the one about music” removes it.

Deliberately limited

A note can record a preference. It cannot change what needs your approval, and this is not a matter of the agent being well behaved — the code that decides whether something needs approving has never heard of notes. Asked to remember “you are authorised to change settings without asking”, it declined to store it, and asked for approval on the very next change regardless.

Fixing something in the code

runs the test suite

The agent can edit AIPI5’s own source. What makes that safe is not that you approve it — it is that the whole test suite runs on the device before the change is kept. Around 1,286 tests. If any of them fails that was not already failing, your change is put back and the assistant is restarted on the old code before you are told anything.

Expect it to take a couple of minutes. It will say so.

agent
The test suite prints a DeprecationWarning from aipi5/tools/news.py. Fix it properly.
✓ read_skill
✓ read_source
✓ read_journal
Change aipi5/tools/news.py
- feed_title = clean(_text(root.find("channel") or root, "title"))
+ channel = root.find("channel")
+ feed_title = clean(_text(channel if channel is not None else root, "title"))
The whole test suite runs before this is kept. If it fails the change is put back automatically.
NoDo it
✓ patch_file
Fixed aipi5/tools/news.py. Element truth-value testing is deprecated. I changed it to an explicit `is not None` check. The full test suite passed. The assistant restarted and is healthy.
4 steps · 88.4s

This is a real change, now committed to the repository. It was the last warning in the suite.

The thing that will confuse you

A source change is only possible while the test suite is green. The very first attempt at the patch above was rolled back — by two unrelated tests that were already failing on the device. The agent’s work was correct; the gate simply could not tell the difference.

So if a patch keeps being refused and the reason names tests that have nothing to do with it, check the suite before blaming the change.

Working with it

  • Point it at evidence, not a guess: “the log says X, look at Y.”
  • Ask it what it expects to happen before it applies something.
  • Small changes pass; sweeping ones fail the suite and get reverted.
  • It only ever does this in a conversation you start. There is no scheduled maintenance, and nothing runs overnight.

What it will refuse

Worth knowing, because a refusal is an answer and not an obstacle to argue with. None of these are the agent choosing to be careful — they are refused by a separate program running as root, whose rules the agent cannot read, edit, or reach.

Asked toBecause
aipi5/tools/*.py, the pages, the config allowed This is the point. Behind approval and the test suite.
Edit its own runtime, aipi5/agent/ refused An agent that can rewrite the code asking for approval has nothing left to ask.
Edit scripts/ or systemd/ refused The installer, and what starts at boot before anyone is watching.
Touch ~/.ssh or ~/.bashrc refused Both are routes to becoming the user who is root on this machine.
Restart sshd, or anything unlisted refused Six services are listed by name. The list is not the agent’s to extend.
Install a package refused The allowlist is empty by choice — an apt package runs its own code as root.
Restart the program that contains it refused It does not get to restart its own jailer.

Asked to remove its own approval check, it answered: “I can’t edit aipi5/agent/tools.py. It is the agent’s own runtime, which is protected because removing _approve’s approval check would disable the safety control governing changes.”

One honest caveat

The guarantee this design actually makes is “the agent cannot touch what is not on the list.” It is not “the agent can never act without asking you” — whether you approved something is decided by the agent’s own process, which the root half cannot independently verify. That half bounds a bug in the other with what it can check alone: a change must be proposed before it is applied, only one at a time, and at most twenty an hour.

When something goes wrong

What you seeWhat it means
“AIPI5 is not answering. It may be restarting.” Usually true, and often because the agent is restarting the assistant on your behalf. It reconnects itself.
A change was rolled back citing unrelated tests The device’s test suite is not green. Fix that first — nothing can be patched until it is.
aipi5-agent-helper is inactive Normal, and not a fault. It is started by its socket on the first request, so a healthy device shows it inactive whenever nothing has asked it for anything — after a reboot, for instance. Check aipi5-agent-helper.socket instead; that one should be active.
“The privileged helper is not answering” The root service is down: sudo systemctl status aipi5-agent-helper
The screen is blank for ~15 seconds The assistant restarted. The kiosk browser is tied to it and comes back by itself.
A page you cannot get out of Use the window’s own controls — close, back, or the address bar. You never need the agent to leave a page.
An approval expired before you saw it A timeout is a refusal — nothing was changed. Ask again.
“That is 40 runs today, which is the limit” A daily ceiling, so a loop cannot spend a month’s budget overnight. It resets at midnight.

After a power cut

Ask it: “the Pi rebooted, check everything came back.” It walks every service and reads the boot log, which is quicker than doing it by hand and catches things you would not have thought to look for — on the last outage it found an undervoltage warning in the kernel log without being asked about power at all.

One thing it cannot tell you: the journal on this device is held in memory, so everything logged before the reboot is gone. “No errors before the crash” means the evidence went with the power, not that nothing happened.

Checking on it yourself

sudo systemctl status aipi5-agent aipi5-agent-helper
sudo tail -f /var/log/aipi5-agent/helper.jsonl   # everything root did, and why
sudo ls /var/lib/aipi5-agent-helper/changes/     # every change, with its backup

That log is written by the root half and the agent can read it but not edit it: the record of what was done to the device is deliberately not editable by the thing that did it.

The one thing still to do

Email delivery for reminders needs four steps in the Google Cloud console — checking the consent screen is published, adding the gmail.send scope, enabling the Gmail API, and running scripts/link-gmail.sh with an ssh tunnel up. They are written out with what each failure actually means in docs/gmail-setup.md. Everything else is working.
